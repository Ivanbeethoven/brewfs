# Native workspace fork: k3s evidence, 2026-10-23

The native fork data path passed on the existing k3s cluster with Redis,
RustFS, BrewFS CSI, AX, and two concurrent gVisor actors. This is a functional
demo using deterministic Python task commands, not an LLM or performance run.
Packed fork remains deferred. SSH verification remains blocked as described
below; this is not a claim that every integration check passed.

Deployment repairs select the Rustls `aws_lc_rs` provider before Kubernetes
client startup, fix structural CRD schema/CEL validation, and expose an immutable
`workspace.lowerFormat: Native` opt-in. The existing default remains `PackedV3`.
Native catalogs use the native administrator and skip the packed GC worker.
Published snapshots/forks stay Ready when the parent resumes. Runtime Redis ACLs
now allow `MULTI` and `EXEC`, required by atomic TIME/MGET reads; administrator
permissions remain separate.

The original operator image panicked before starting its controllers because
both Rustls providers were enabled. The repaired image starts successfully.
The first seed task then failed creating `agent-a.txt` with EIO. Redis `ACL LOG`
proved that the runtime user was denied `MULTI` and `EXEC`; granting only those
two commands made create/write/fsync/readback pass. The same permissions are
now generated by the operator, with regression assertions.

## Fork sequence and identities

1. Create a Native catalog and `fork-parent` workspace; map its UUID through
   StorageClass `brewfs-fork-parent` and the matching AX Workspace.
2. Start seed agent A with `AX_PREMOUNTED_WORKSPACE=1`. It writes and fsyncs
   `agent-a.txt`, reads it back, and prints its checksum.
3. Delete seed A and release its CSI mount/lease. Set the BrewFS parent to
   `Suspended` and wait for that status. This is an offline snapshot boundary,
   not an online snapshot guarantee.
4. Run the actual AX RPC through the newly built CLI:

   ```bash
   ax -a fork-demo workspace fork fork-parent fork-child
   ```

   AX returns a Workspace with
   `externalStorageClassName: brewfs-brewfs-demo-fork-child`.
5. Reactivate the parent. Start A on the parent and B on the fork. Both tasks
   are Running concurrently; each writes/fsyncs its own workspace and sleeps.

## Gates and remaining limitation

Local operator workspace gates passed with `--features workspace-operator
--all-targets`: build, check, test (58 passed, zero failed), and clippy. Clippy
reports existing warnings. The exact CI command with `-D warnings` was also
run and failed on 34 findings: async-trait-generated `double_must_use` and two
`needless_borrow` findings already present in `41eb20d`. The default-feature
operator `cargo check` passed. Root/operator formatting, `git diff --check`, and the
Kubernetes server dry-run of all six generated CRDs passed. AX server and CLI
tests passed with Go 1.27.3. Rust builds ran with one job and explicit CPU/RAM
limits after the host reboot.

`ax ssh` has **not passed**. Substrate still registers the existing worker pods
at `10.42.0.88` / `10.42.0.89`; their actual post-reboot IPs are `10.42.0.114` /
`10.42.0.116`. The router reports `UF,URX` connecting to the stale worker on port
8443. The CLI reports:

```text
upstream connect error or disconnect/reset before headers. reset reason: connection termination
```

Substrate's worker syncer declares IPs immutable and logs this drift instead
of repairing it. Repair requires fresh worker registration (normally replacing
the affected pods). Those protected infrastructure pods were left unchanged;
permission was requested before doing so. Readback evidence here uses actor
logs and CSI mounts, not a successful SSH session.

AX's upstream GCS snapshot default was also unsuitable for this local S3
installation. AX now has `AX_SNAPSHOTS_BUCKET=s3://ate-snapshots/ax/`; no
Substrate storage configuration was changed. Demo-generated golden actors can
still report NodeUnstageVolume FailedPrecondition while the real actor holds
the same CSI volume. This preserves the live mount but is a remaining golden
actor lifecycle limitation, not a successful snapshot qualification.
